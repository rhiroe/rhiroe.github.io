値オブジェクトと
composed_ofと
Attributes API(CustomType)

Railsで値オブジェクトを活かすための2つの機能を整理する

はじめに

"値オブジェクト"という言葉をDDDの流行とともによく耳にするようになりました。

そして値オブジェクトというワードとともに composed_of というRailsの機能を耳にすることも増えました。

composed_ofは本当に「値オブジェクトのための機能」なのか？を整理します

値オブジェクトとは

不変性と等価性の性質を持つ「値」を表現するため抽象化された概念

よく例として目にするのは"お金"です。

Rubyには値オブジェクトを定義するための Data クラスがあるため、こちらを利用して簡単に作ることができます。

Money = Data.define(:amount, :currency)
Money.new(amount: 1_000, currency: '¥')

composed_of

Railsには Rails2系から存在する、複数の値を1つのオブジェクトにまとめる composed_of という機能があります。

  • 値オブジェクト云々が広く話題になる前から存在する機能
  • しかし値オブジェクトのための機能かのように語られるのをよく見る

composed_of は複数のカラムの値で構成されたオブジェクトを扱うための機能であり、値オブジェクトのための機能ではありません

値オブジェクトと composed_of

composed_of は値オブジェクトのための機能ではありませんが、値オブジェクトを活用するために使える機能です。

class User < ApplicationRecord
  Address = Data.define(:postal_code, :prefecture,
                         :city, :street, :building)
  composed_of :address, class_name: 'Address', mapping: {
    postal_code: :postal_code, prefecture: :prefecture,
    city: :city, street: :street, building: :building
  }

  FullName = Data.define(:first_name, :middle_name, :last_name)
  composed_of :fullname, class_name: 'FullName', mapping: {
    first_name: :first_name, middle_name: :middle_name,
    last_name: :last_name
  }
end

composed_ofの本来の使い方ではない例

composed_of は値オブジェクトのための機能と思って使うと下記のような状態になることがあります。

class Invoice < ApplicationRecord
  YearMonth = Data.define(:reference_date) do
    def initialize(**kwargs)
      kwargs[:reference_date] =
        kwargs[:reference_date].beginning_of_month
      super
    end
  end

  composed_of :target_month, class_name: 'YearMonth', mapping: {
    reference_date: :reference_date
  }
end

複数の値で構成されたオブジェクトを扱っているわけではなく、カラムの値を別の型に変換するために使われている

何が問題なのか

composed_ofが得意なこと

  • 複数カラム → 1つのオブジェクト
  • 例：郵便番号・都道府県・市区町村…
    → 住所オブジェクト

やろうとしていること

  • 単一カラム → 別の型への変換
  • 例：Date型のカラム
    → YearMonthオブジェクト

composed_of は等価性比較・演算子オーバーロード・
mappingアクセサ経由のクエリ発行など、値オブジェクトを「組み立てる」ための機構を前提にした機能

単にカラムの値を別の型に変換したいだけなら、そうした機構は不要なオーバーヘッドになります。

もう一つの選択肢
Attributes API(CustomType)

型を変換するための機能もRailsには備わっています。

  • ActiveRecord::Type を継承したカスタム型を定義
  • attribute でカラムに紐づける
  • cast / serialize でDBとオブジェクトを相互変換

カラムの値を別の型に変換する場合はこちらの機能を使う方が適しています

Attributes APIによる実装

class Invoice < ApplicationRecord
  YearMonth = Data.define(:reference_date) do
    def initialize(**kwargs)
      kwargs[:reference_date] =
        kwargs[:reference_date].beginning_of_month
      super
    end
  end

  class YearMonthType < ActiveRecord::Type::Date
    def cast(value)
      if value.is_a?(YearMonth)
        value
      elsif value.is_a?(::Date)
        YearMonth.new(reference_date: value)
      elsif value.respond_to?(:to_date)
        YearMonth.new(reference_date: value.to_date)
      end
    end

    def serialize(value) = super(value&.reference_date)
  end

  attribute :reference_date, YearMonthType.new
  alias_attribute :target_month, :reference_date
end

まとめ

  1. 値オブジェクトを活かすためのRailsの機能を2つ紹介したが、どちらも値オブジェクトのための機能ではない
  2. composed_of は複数カラム→1オブジェクトのマッピングに使う
  3. Attributes API(CustomType) は単一カラムの型変換に使う

Railsの機能を目的に合わせて適切に使い分けていきましょう
