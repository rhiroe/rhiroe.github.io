# Railsのlibに何を置くか

## よく聞く話

Railsの`lib`には「将来gemに切り出せるような汎用的なコード」を置くと言われている。

でも「本当にgemにするの？」って聞かれたら大体Noだと思う。

## 別の基準

最近考えているのは、こういう分け方。

```
lib/    → ビジネス要件の変更に影響されないコード
app/    → ビジネス要件の変更で変わりうるコード
```

## 外部APIクライアントの話

例えば外部APIクライアント（Slackとか決済サービスとか）。

これは自社のビジネス要件じゃなくて外部サービスの仕様に依存している。ビジネスロジックが変わってもクライアント自体は変わらない。

だから`lib`に置く。

```
lib/
  slack_client.rb      # 外部仕様に依存

app/
  services/
    slack_notifier.rb  # どんな通知を送るかのビジネスロジック
```

## 何が嬉しいか

ディレクトリ構造でコードの性質が伝わる。

- `lib/`にあれば「ビジネスの文脈知らなくても読める」
- `app/`にあれば「ビジネスの文脈理解して読む必要がある」

新しく入った人にもこれが伝わる。

## コスト

ビジネスロジックを混ぜないようにする設計努力は必要。設定の外部注入とか。

ただこれは「libに置くため」じゃなくて「ビジネスロジックと外部依存を分離する」ための作業なので、やる価値はあると思っている。

## 判断基準

迷ったら「このコードが変更される理由は何？」を考える。

- 外部仕様の変更で変わる → `lib/`
- ビジネス要件の変更で変わる → `app/`
